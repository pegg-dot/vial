# VIAL 7.0 — Governed Extraction (Agent Control Plane)

**Status:** approved design · 2026-07-19
**Base:** verified 6.0 (`evidence-laboratory-network`) + cart-crash fix, commit `59bebf7`

## Thesis

Make model-assisted extraction *measured*, not assumed. Build the measurement gate
first, benchmark the deterministic baseline, run a model in shadow, and only promote
the model to live if it beats the baseline on a golden dataset. Every model-produced
claim still passes through the existing human publication gate. Fold in two security
fixes from the 6.0 audit.

## Non-negotiable boundaries (unchanged from 0.1–6.0)

- Model output is *candidate claims only*. It never controls auth, permissions,
  publication, payments, or transaction eligibility.
- Every claim — deterministic or model — enters `evidence_claims` at
  `review_status='pending'` and requires a human decision to publish.
- Source content is hostile data. Model output is bounded by the same zod
  `claimCandidateSchema`; anything off-schema is rejected/abstained, never trusted.
- No LLM becomes the live extractor until a benchmark run proves it beats the
  deterministic baseline.

## The seam

`src/server/agents/pipeline.ts:191` (Clerk stage) currently calls
`extractClaimCandidates(input): ClaimCandidate[]` directly. `evidence_claims` already
has `extractor_version` and `model_confidence` columns. We replace the direct call with
a selected `ExtractorProvider`. Nothing downstream (Resolver/Verifier/Auditor/review/
cascade) changes.

## Architecture — mirror the commerce provider pattern

Commerce swaps `mock` vs `stripe` behind one interface with an env selector
(`src/server/commerce/providers/{mock,stripe,index}.ts`). We mirror it exactly.

```
src/server/agents/extractors/
  types.ts          ExtractorProvider interface + ExtractionResult
  deterministic.ts  wraps existing extract.ts (unchanged logic)
  model.ts          Anthropic-backed, zod-bounded, budgeted
  anthropic-client.ts  thin client wrapper; injectable mock for tests
  index.ts          getExtractor() selector, env VIAL_EXTRACTOR
```

```ts
interface ExtractorProvider {
  readonly id: string;            // "deterministic-v2" | "model-<promptVersion>"
  extract(input: ParsedIngestionInput): Promise<ExtractionResult>;
}
interface ExtractionResult {
  candidates: ClaimCandidate[];   // validated against claimCandidateSchema
  extractorVersion: string;
  costCents: number;              // 0 for deterministic
  abstained: boolean;             // true when the extractor declined
  meta?: Record<string, unknown>;
}
```

Selector: `VIAL_EXTRACTOR = deterministic (default) | model | shadow`.
No `ANTHROPIC_API_KEY` → model/shadow silently fall back to deterministic
(fail-closed, no crash).

## Part 0 — Hardening (folded in)

**0a. Deny-by-default perimeter.** `src/server/auth/access-policy.ts` currently returns
`{protected:false, allowed:true}` for unmatched routes. Invert: maintain an explicit
PUBLIC allowlist (`/`, `/market`, `/compounds`, `/vendors`, `/products`, `/compare`,
`/search`, `/methodology`, `/about`, `/help`, `/legal/*`, `/status`, `/operations`,
`/signals`, `/passports`, `/labs`, `/login`, `/api/health/*`, `/api/v1/health`,
`/api/v1/catalog`, `/api/v1/alerts`, `/api/openapi.json`, static assets); everything
else is `protected:true`. Per-page/per-API guards stay (defense in depth). New test
`tests/unit/access-policy.test.ts` asserts an unknown route (`/newthing`) is protected.

**0b. Real commerce kill-switch.** `commerce_production` flag is currently dead.
Make live payments require BOTH env config (existing `validateCommerceSafety`) AND the
DB flag explicitly enabled. `getPaymentProcessor()` reads the flag; flag off ⇒ mock
provider regardless of env. Default off. Test asserts flag-off forces mock even with
stripe env set.

## Part A — Measurement gate (no model, no API cost)

**Schema (migration 9, `agent-control-schema.ts`):**
- `agent_prompts` (id, prompt_key, version, template, tool_schema jsonb, status
  draft|active|retired, notes, created_at, activated_at) — immutable versions.
- `extraction_golden_cases` (id, dataset_version, name, html, content_type,
  parser_profile, expected_claims jsonb, difficulty, note) — hand-labeled fixtures.
- `extraction_benchmark_runs` (id, extractor_id, prompt_version, dataset_version,
  precision, recall, f1, abstention_correct_rate, avg_cost_cents, case_count,
  created_at).
- `extraction_benchmark_case_results` (id, run_id, case_id, predicted_claims jsonb,
  tp, fp, fn, correct_abstention bool).
- `extractor_activations` (id, extractor_id, prompt_version, activated_by,
  reason, active bool, created_at) — audit + rollback pointer.

**Golden dataset seed** (`src/server/agents/golden-seed.ts`): ~12 fictional messy HTML
cases — JSON-LD offers, visible-text-only, missing fields, conflicting values,
prompt-injection strings in body, noisy markup, empty/nothing-extractable (abstention
cases). Each with hand-labeled `expected_claims`.

**Scorer** (`src/server/agents/benchmark.ts`): `scoreExtraction(predicted, expected)`
→ per-predicate TP/FP/FN, precision/recall/F1, and abstention-correctness (did it
correctly emit nothing when expected empty). `runExtractionBenchmark(extractorId,
datasetVersion)` runs an extractor over the golden set, writes a benchmark run + case
results. Baseline = deterministic extractor benchmarked at build time.

## Part B — Shadow + rollback

**Shadow mode** (`VIAL_EXTRACTOR=shadow`): pipeline runs deterministic (authoritative —
its candidates flow to review) AND the model in parallel; logs model output + a diff to
`extraction_shadow_runs` (id, agent_run_id, deterministic_claims jsonb, model_claims
jsonb, agreement_rate, cost_cents, created_at). Model claims NEVER reach review. Model
failure/timeout/over-budget in shadow is swallowed + logged, never breaks the run.

**Rollback:** activating an extractor/prompt version writes `extractor_activations` with
`active=true` and flips prior to false (one active per extractor_id). Admin-only server
action. Revert = re-activate the prior version. Live selector consults the active
pointer for the model prompt version.

## Part C — Live Claude extractor (gated on Part A)

**`ModelExtractor`** (`model.ts`) using `@anthropic-ai/sdk`, model
`claude-haiku-4-5-20251001` (cheap/fast; extraction is bounded):
- Builds a message from the active versioned prompt + the snapshot text (framed as
  untrusted data) + a strict tool/`tools` structured-output schema mirroring
  `claimCandidateSchema`.
- Parses tool output, validates every candidate with `claimCandidateSchema`; drops any
  invalid/off-vocabulary item; if nothing valid → `abstained:true`, empty candidates.
- **Per-run budget:** max input+output tokens per extraction from env
  (`VIAL_EXTRACTOR_MAX_TOKENS`, default e.g. 4000). Estimated overage ⇒ abstain + log.
  Aggregate daily budget (`VIAL_EXTRACTOR_DAILY_BUDGET_CENTS`) tracked in
  `extraction_shadow_runs`/benchmark cost; over budget ⇒ abstain.
- Records `extractor_version = "model-<promptVersion>"`, `model_confidence` per claim.
- **Ship gate:** `model` selectable in live (non-shadow) mode only after a
  `extraction_benchmark_runs` row for the model beats the deterministic baseline
  (higher F1, or equal F1 at lower cost / better abstention). Enforced in `index.ts`
  selector: if `VIAL_EXTRACTOR=model` but no passing benchmark exists ⇒ refuse + fall
  back to deterministic + log.

**Anthropic client** (`anthropic-client.ts`): thin wrapper; `createExtractionClient()`
returns real SDK client when `ANTHROPIC_API_KEY` set. `ModelExtractor` takes the client
by injection so tests pass a deterministic **mock** client (returns canned tool output)
— test suite needs no key and no network, exactly like commerce's mock provider.

## Admin surface

Extend `/admin/agents` (existing agent-evaluations page) into the control plane
(staff-gated, existing perimeter): baseline vs model benchmark table, prompt versions +
active pointer, shadow-run diffs, activation/rollback history, budget status. Read views
server-rendered; activation/rollback are admin-only server actions.

## Testing (TDD)

**Unit:**

- benchmark scorer math (precision/recall/F1, abstention-correct).

- budget enforcement → abstain.

- full pipeline still green with deterministic default (no regression).

Anthropic client behind `ANTHROPIC_API_KEY` — mirrors how Stripe is smoke-tested, never
in CI.
