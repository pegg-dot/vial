# VialGrade 8.0 — Ambient Delivery

**Status:** approved design · 2026-07-19 · base = 7.0 tip (9868238)
**Constraint:** not optimizing for mobile yet — build device-agnostic ambient
infrastructure, defer camera scanner + mobile-responsive polish.

## Thesis

VialGrade already *creates* notifications when a reviewed change happens
(`syncWatchlistNotifications` → `user_notifications`). 8.0 gives it the ability to
*reach out*: self-hosted web push, an offline service worker, and installability —
all in the verifiable web stack, no external provider.

## Boundary

Web push is browser-native and self-hosted via VAPID keys. It adds none of the
"still external" providers (email / SMS / identity). Push fires **only** on
reviewed notifications — it inherits the human-review gate and never delivers
crawler noise.

## Scope

**Migration 10 (schema v10) — `push_subscriptions`**: id, user_id (FK auth_users),
endpoint (UNIQUE), p256dh, auth, user_agent, created_at, last_seen_at.

**`src/server/push/`**
- `vapid.ts` — `getVapidConfig()` reads `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/
  `VAPID_SUBJECT` from env; returns null when unset (push disabled, fail-safe).
- `repository.ts` — saveSubscription (upsert on endpoint, scoped to user),
  removeSubscription, getSubscriptionsForUser, deleteByEndpoint (prune).
- `delivery.ts` — `sendPushToUser(userId, payload, sender?)`: loads the user's
  subscriptions, sends via an injectable `web-push` sender (mock in tests), prunes
  a subscription on 404/410, no-ops when VAPID is unset. Never throws.

**API (`/api/v1/push/*`, auth = any principal)**
- `GET vapid-public-key` — the public key for the browser to subscribe.
- `POST subscribe` — store the PushSubscription for the current user.
- `POST unsubscribe` — remove by endpoint.

**Hook**: in `syncWatchlistNotifications`, after each `upsertUserNotification`,
best-effort `sendPushToUser` (try/catch — notification creation never breaks).

**Service worker (`public/sw.js`)**: install (cache app shell), fetch (offline
app-shell fallback for navigations), push (show notification from payload),
notificationclick (focus/open the action URL).

**Client**
- `service-worker-registrar.tsx` — registers `/sw.js` on mount (in root layout).
- `push-subscription.tsx` — "Enable delivery" control on `/account/notifications`:
  registers SW, requests permission, subscribes with the VAPID public key, POSTs
  to subscribe; shows permission + subscription state; unsubscribe.

**PWA**: manifest already has name/short_name/standalone/icons — installable once
the SW registers. No change needed beyond registration.

## Deferred (mobile phase)

Camera QR / batch-passport scanner; mobile-responsive layout polish.

## Testing (TDD)

- Unit: vapid config (env matrix, null when unset); delivery targets only the
  user's subscriptions; prunes on 410; no-ops when VAPID unset; never throws;
  payload build.
- Integration (PGlite, mock sender): subscribe stores per-user; a second user's
  send never reaches the first user's endpoint; a reviewed notification triggers a
  send.
- Live smoke: `/sw.js` registers, `/account/notifications` renders the
  enable-delivery control, offline app-shell loads, build clean.
- **Honest limit**: a real push landing on a physical device needs a real browser +
  the push service — out of headless scope. Plumbing + send logic are verified.

## New env

```
VAPID_PUBLIC_KEY=            # unset ⇒ push disabled (fail-safe)
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=mailto:ops@vialgrade.example
```
Dev keypair generated via `npx web-push generate-vapid-keys`; prod supplies its own.
