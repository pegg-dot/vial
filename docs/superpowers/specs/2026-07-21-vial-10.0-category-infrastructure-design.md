# VIAL 10.0 — Category Infrastructure (Standards Layer)

**Date:** 2026-07-21
**Status:** Approved for build
**Preceding version:** 9.x (enterprise completion — risk feeds, research terminal, lab analytics)

## Thesis

VIAL has already built the two hardest assets a standards layer needs — a root-attached
**historical provenance graph** and a conflict-preserving **cross-lab corroboration graph** —
but they run on two different, unreconciled identity spines, and neither is publicly
addressable. **10.0 is not a new feature layer; it is the act of unifying those two spines
into one public, resolvable registry and pointing it outward.**

This converts VIAL from "a premium comparison site with a private graph" into "the addressable
standard the rest of the ecosystem cites."

## What compounds (the loops 10.0 closes)

- **Loop A — Historical provenance (time moat).** `publication_events` + `domain_events`/`trace_edges`
  + the cascade keep every reviewed change dated, versioned, and attached to its causal root.
  Value grows with observations over time; unreconstructable by a new entrant.
- **Loop B — Cross-lab corroboration on a batch (participation network effect).** When independent
  samples of the same batch disagree, the dimension is `conflicting` and both are kept — VIAL never
  averages disagreement away. Each additional independent observer densifies a batch's record. This
  is the most under-exploited asset in the codebase.
- **Loop C — Identity ↔ alias resolution (the spine).** More observations → better resolution →
  cleaner merges → a spine that attracts more data.
- **The flywheel:** public VIAL IDs → outside labs/vendors attach evidence against them → densifies
  Loop B → IDs become more authoritative → drives adoption. VIAL has every asset for this and has
  never closed it, because evidence is trapped behind internal slugs.

Reputation is the **emergent product of A + B** and must never be a stored score — an accumulated,
dated, provenance-linked record is anti-black-box by construction. This closes back to the founding
"Experian-like historical graph" vision.

## What we fix (defects surfaced by the audit)

- **Two unreconciled spines.** `rebuildCanonicalGraph` synthesizes lab/report/batch entities from the
  `listings.report_issuer` free-text string and never ingests `laboratory_profiles` /
  `laboratory_reports` / `batch_passports`. **#1 unification.**
- **No public resolvable identity.** Everything public is slug-addressed; canonical IDs are never URIs.
- **Slug-coupled identity re-mints on rename**, orphaning the old entity and its FKs.
- **Batch identity is a fuzzy `LOWER()` string join**; the most valuable object is the least canonical.
- **Reputation scattered across ~8 ad-hoc signals** with no composed surface.
- **`support_score` / `median_ship_days`** render as authoritative vendor scores but are fabricated
  static seeds with no derivation — a live violation of the no-black-box doctrine.
- **Batch passports mutate in place** with no version history despite being the thing you'd cite.
- **`evidence_confidence` flattens** lab identity + method + independence into one scalar.
- **Version drift:** `package.json` says 7.0.0, API says 9.0.0; `verify:v7/v8/v9` alias `verify:v6`.

## Boundaries preserved (AGENTS.md)

Information-only (no payments/dosing); publishes only reviewed events + issued reports; unknown stays
visible; confidence explicitly "not a safety score"; keys hashed + revealed once; per-tenant isolation;
no MCP/bearer-token path may publish or approve evidence.

## Deliverables

### D1 — Canonical Identity Registry + public resolver (keystone)

- **`registry_identifiers`** table: immutable, human-legible `vial_id` (`vial:compound:tirzepatide`,
  `vial:lab:aperture`, `vial:vendor:...`) keyed by **stable source identity** (`source_entity_type`
  + `source_entity_id`), not slug — so a rename reuses the same `vial_id`. Carries `current_entity_id`
  (pointer to the live projection row), `status` (active|redirected|retired), and `redirects_to`
  (for merges).
- **`mintVialId`** — idempotent minter: reuse existing id for a known source, else mint from the slug
  with collision suffixing; record a former slug as an alias when it changes.
- **Unify the spines:** extend `rebuildCanonicalGraph` to ingest real `laboratory_profiles` and
  `batch_passports`, replacing string-derived lab/batch stand-ins with references to the real records.
- **Resolver:** `GET /api/public/v1/id/{vialId}` (record + aliases + relationships + provenance pointer,
  follows redirects) and `GET /api/public/v1/resolve?label=&type=` (reuses `resolveEntityLabel`).
  New scope `identity:read`. Resolve is bearer-authed like the rest of the public API.
- **Verify:** idempotent minting; vial_id stability across a rename; messy-alias → vial_id resolution;
  spine unification (a lab record produces a real `vial:lab:*` id linked to its reports).

### D2 — First-class Batch entity + versioned passport + decomposed confidence

- **Canonical batch** keyed by (vendor + compound + normalized declared code); a `vial:batch:*` id via
  the registry. Retire the fuzzy `LOWER()` join.
- **`passport_versions`** append-only table; `recomputePassport` writes a new immutable version instead
  of mutating in place. The cited passport URL is stable; history is queryable.
- **Decompose `evidence_confidence`:** keep the headline number but emit its components (which labs,
  independence model, methods, dimensions established/unknown/conflicting) for API + page.
- **Public:** `GET /api/public/v1/batches/{vialBatchId}` (bearer, `market:read`).
- **Verify:** two independent labs both shown + conflict preserved + independence exposed; recompute
  writes a version rather than overwriting; a revoked report is reflected in the public projection.

### D3 — Composed Reputation Records (decomposable, never scored)

- **Read-model** composing scattered signals into per-vendor and per-lab records; each dimension
  **dated + provenance-linked + independently visible**, with explicit "unknown" where absent and
  **no composite number**. Reuses `entity_metric_snapshots` as the already-written-but-never-read
  time series.
- **Fix the doctrine violation:** replace fabricated `support_score` / `median_ship_days` on the vendor
  page with real, provenance-linked dimensions (or explicit "unknown").
- **Public:** `GET /api/public/v1/reputation/{vialId}`, scope `reputation:read`.
- **Verify:** a vendor with an unresolved conflict shows it without lowering a hidden score; a vendor
  with no evidence shows "unknown," not "0."

### D4 — External evidence submission against canonical IDs (flywheel, proposal-only) [stretch]

- Authenticated lab/vendor submits a report/claim referencing a public VIAL id, routed into the
  existing `laboratory_work_proposals` + human-review + publication gate. **Never auto-publishes.**
- **Public:** `POST /api/public/v1/id/{vialId}/evidence-proposals` (bearer, proposal-only).
- **Verify:** a lab token submits against a batch id → lands as a proposal → after review appears on
  the passport under a new root event.

### D5 — Published contract + forward migrations + verify:v10

- **Published data dictionary** (canonical types + ID scheme + reputation dimensions) at `/developers`
  (or `/methodology`), versioned.
- **Migration drift check:** a test that fails if `schema.ts` diverges from what migrations apply.
- **`verify:v10`** registry audit (`audit:registry`) instead of aliasing `verify:v6`.
- **Housekeeping:** bump `package.json` to 10.0.0; fix stale `ARCHITECTURE.md` limitations.

## Build order

D1 (keystone) → D2 (batch + versioned passport) → D3 (reputation + doctrine fix) → D5 (contract +
discipline) → D4 (flywheel, if the build stays healthy). One clean commit per deliverable, TDD
throughout (test-first, watch-fail, minimal implement). Final gate: `verify:v10` + full
lint/typecheck/test/build, then an adversarial multi-agent review pass before completion.

## Non-goals

- No composite/black-box score anywhere.
- No auto-publish from any bearer/MCP path.
- No real commerce, payments, dosing, or human-use guidance.
- No unrelated commerce-v1/v5 dedup (out of standards scope; noted, deferred).
- No object-storage / worker-queue infra migration (scale hardening, not 10.0-defining).
